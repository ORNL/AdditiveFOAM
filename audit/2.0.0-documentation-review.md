# AdditiveFOAM 2.0.0 Documentation Review

This internal release audit is excluded from the generated GitHub Pages site.

## Audit basis

- Repository: `ORNL/AdditiveFOAM`
- Candidate branch: `candidate-v2.0.0`
- Audited commit: `8f709f8a46462cdb38c183e96e98b28a23b370a1`
- Release PR: #95
- Surface reviewed: solver, moving heat-source library, boundary conditions, function objects, utilities, helper scripts, material fragments, tests, and all tutorial files changed by the release PR

Re-run the file and dictionary audit if the candidate SHA changes before release.

## Release-blocking documentation/source alignment

1. `etc/bashrc` still exports `ADDITIVEFOAM_VERSION=2.0.0-dev`. Change it to the final release identifier before tagging.
2. `CHANGELOG.md` stops at release 1.1 even though the candidate is for 2.0.0. Add a 2.0 section covering OpenFOAM 13, new source models, adaptive integration/refinement, dynamic load balancing compatibility, thermodynamic schemes, utilities, function objects, and compatibility changes.
3. The ExaCA function object throws a fatal error from `distribute(const polyDistributionMap&)`. It therefore cannot be combined with the highlighted runtime load-balanced AMR workflow. Decide whether this is an accepted 2.0 limitation or a release blocker; the website currently documents it as a limitation.
4. No released tutorial currently enables the full `targetCellLoad` + OpenFOAM `loadBalancer` + Zoltan workflow. The website supplies a configuration recipe, but a maintained runnable tutorial would materially reduce regression risk for this headline feature.
5. The supplied tutorials default to Euler with `explicitSolve true`; none directly exercises the highlighted second-order thermodynamic path. Consider adding a regression/tutorial variant with `backward` and `explicitSolve false`.

## Correctness and clarity findings

- Tutorial directories contain `0/alpha.solid`, but `createFields.H` constructs `alpha.solid` with `NO_READ` and `NO_WRITE`. Remove the unused files or explain their compatibility purpose to avoid implying that they initialize the phase field.
- Tutorial `dynamicMeshDict` headers still identify OpenFOAM version 11 while the candidate requires OpenFOAM 13.
- The solver log message `thero time coefficient (coefft)` contains a typo; documentation quotes it exactly so users can find it.
- `refinementModel::refinementModelDictName` is initialized as `refinementModelDict`, while the runtime configuration is read from the `refinementModel` subdictionary. The constant appears unused but is misleading to future maintainers.
- PR #95's description says `v2.0.0.0`; correct it to `v2.0.0` before release.
- `runLayers` removes existing `layerN` directories. The website warns users, but the script should ideally require an explicit overwrite flag or emit a stronger confirmation-safe failure.
- `plotDimensions` initializes axis limits to infinities and may fail if all requested cases lack data. It currently emits warnings but should avoid applying invalid limits.

## Documentation decisions

- The 2.0 installation guide documents only the OpenFOAM Foundation 13 source workflow verified by the candidate README and environment check. It does not carry forward unverified Spack or Docker instructions.
- `alpha.solid` is documented as derived from `T` and `thermoPath`, not as an input.
- Adaptive heat-source integration distinguishes spatial `nPoints` sampling from beam temporal subcycling via `deltaT`.
- Load-balanced AMR is described as a composition of AdditiveFOAM refinement targeting, OpenFOAM's topology changer/load balancer, and Zoltan redistribution.
- Second-order support is described as an implicit feature. `explicitSolve true` may force forward Euler when the explicit stability criterion is satisfied.
- Release links use the immutable `2.0.0` tag and will remain broken in remote external-link checks until that tag exists; merge the Pages PR only at release.
