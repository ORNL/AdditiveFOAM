# AdditiveFOAM 2.0.0 documentation review

## Audit basis

- Pull request: [ORNL/AdditiveFOAM #103](https://github.com/ORNL/AdditiveFOAM/pull/103)
- Source of truth: fetched `origin/Calibration`
- Audited source commit: `6dfd9c2618601e13ea85e00bb3df68fa58260596`
- Review date: 2026-08-31
- Read-only source snapshot: `/tmp/additivefoam-calibration-6dfd9c2`

The live Pages documentation was compared with the exact C++, Python, tutorial,
configuration, `CHANGELOG.md`, and README content at that commit. Runtime names,
defaults, equations, dictionary structure, utility behavior, tutorial inputs, and
calibration schemas were checked at their implementation sites. The historical
`1.0.0/` pages were outside the audit scope.

## Release behavior represented by the live pages

- OpenFOAM Foundation 14 and Python 3.10--3.12.
- The top-level `sources` dictionary, named sources, and nested `absorption`,
  `heatSource`, `profile`, and `projection` selections.
- The volumetric `superGaussian` and `modifiedSuperGaussian` models, plus the
  `projected` model with `superGaussian`, `nLightAFX`, or `tabulated` planar
  profiles and the `exponential` projection.
- Source-level `widthReference`, `D4Sigma`, `depthReference`, and `isotherm`
  controls; the distinction between reference depth and applied source depth.
- Exact planar profile moments, principal and area-equivalent `D4Sigma`, profile
  azimuth, and the shared reference aspect ratio
  \(a=2d_{\mathrm{ref}}/D_{\mathrm{ref}}\).
- Analytical normalization, one-sided beam-relative support, tolerance-derived
  bounds, source-bound midpoint sampling, source-state synchronization, and
  moving-source time integration.
- Constant and Kelly absorption using the same selected reference dimensions,
  including the implemented Kelly switch and global `etaMin` lower envelope.
- The flat `refinement { model ...; }` interface and current AMR volume accounting.
- PRIMES conversion, `tabulatedProfileInfo`, and the projected-source calibration
  workflow using deterministic posterior quadrature and robust global fitting.

## Documentation and generator changes

The landing pages, installation and theory guides, heat-source, calibration, AMR,
boundary-condition, case-file, and utility references, tutorial index, and all
six live tutorial pages were reconciled. Examples follow the runtime nested
dictionary structure and use the implemented names and defaults. A profile-metrics
figure and derivation were added so that the selected diameter, reference aspect
ratio, Kelly input, and projected-depth closure can be followed from the planar
moments.

The visualization scripts now consume the current calibration CSV/YAML schema,
display `nSlope`, `nIntercept`, and `2*Depth / selected diameter`, use current
nLight coefficients and projected-model labels, and implement the current Kelly
curve. The regeneration manifest contains 22 assets, including
`profile-metrics.png`.

## Source-backed asset provenance

Freshly rendered AMB2018 temperature and power, multi-beam, multi-layer, nLight
AFX, and tabulated assets use completed runs with the exact current tutorial
inputs. Those runs were produced by the immediately preceding 2.0 implementation
snapshot, before the final change that passed the shared reference aspect ratio
directly into the exponential projection and guarded its logarithm with
`VSMALL`. This does not change these saved results: all projected tutorial and
calibration trials use `nSlope 0`, and the standalone tabulated tutorial also
uses a constant reference depth. An exact-tip solver rerun was not available.

The same capture contains the source-compatible 50-run calibration campaign:
five SS316L conditions and ten `nIntercept` trials per condition. Its fit reports
`nSlope = 1.5727242016483278`, `nIntercept = 1.0596159505244942`, and
`x_definition: 2*Depth / selected diameter`.

The retained AMR animation and still, and the AMB melt-pool-dimension and CET
histories, use the previously completed 2.0 tutorial runs because the fresh
commit-matched capture did not contain a completed AMR variant or the two
post-processing data sets. They were not replaced with synthetic data. All
analytic/profile figures and the calibration plots were regenerated from current
configuration or campaign outputs.
